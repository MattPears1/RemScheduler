5.4.3 The Scheduler's New Logic:
The background scheduler process on Heroku now has a more complex job. It's no longer just firing off individual timers.
The scheduler checks for task_sequences whose start_time has arrived and whose status is QUEUED.
When found, it changes the sequence status to RUNNING. It then finds sequence_steps where step_number is 1 for that sequence.
It calculates the scheduled_time for this first step and sends the execution job to the Local Agent via WebSockets.
The agent executes the job and reports back job_complete or job_failed.
Upon receiving job_complete, the backend updates the sequence_steps status to COMPLETE. It then immediately looks for the next step (step_number 2). It calculates the next scheduled_time (current time + the sequence's interval_seconds) and sets a timer to send that job.
This process repeats until the last step is complete, at which point the parent task_sequences status is set to COMPLETE.
6.0 Robustness and Error Handling for Sequences
A 10-step sequence is useless if it breaks at step 2 and you don't know why. Robust error handling is paramount.
6.1 Local Agent Enhancements:

Clear Feedback: The WebSocket messages from the agent to the backend must be explicit: job_complete(step_id), job_failed(step_id, reason).
6.2 Backend Sequence State Management:

User Notification: When a sequence is paused due to failure, the system should send an email notification to the user: "Project Aether Alert: Sequence 'Deploy New Feature' was paused at Step 4 of 10. Reason: Target window not found."
Manual Intervention: The user can then log in, see the paused sequence, diagnose the problem (e.g., restart a crashed server in the command prompt), and manually click a "Resume" button. The system would then re-attempt the failed step.

5.3.2 Backend API Logic (POST /api/schedule):

Check the "different messages" toggle value.

Get the single message_text from the submission.
Loop from 1 to repetitions. In each loop:

If toggle is ON:
Get the array of different messages from the submission.
Loop through the array. In each loop:
Calculate the scheduled_time for that step.
Create a new row in the scheduled_jobs table with the job_group_id, the specific message for that step, and the calculated scheduled_time.
Return a success response.

19.3 Feature: Rescheduling a Scheduled Message (with Sequence Integrity)
User Goal: "The job scheduled for 3:00 PM needs to happen later, at 5:00 PM. If it's part of a sequence, I expect all subsequent steps to be pushed back accordingly to maintain the intervals."
UI/UX Implementation: Next to each pending job, there will be a "Reschedule" button.
Clicking "Reschedule" opens a dialog with a date and time picker.
The user selects the new desired time for that specific job and clicks "Confirm."
The Mission Control view refreshes, showing the new times for the rescheduled job and all subsequent jobs in its sequence.
Backend Architecture (This is a critical, multi-step transaction):
This requires a new endpoint: POST /api/jobs/{id}/reschedule.
The request body will contain the new time: { "new_scheduled_time": "2025-08-01T17:00:00Z" }.
The backend logic must preserve sequence integrity:
Retrieve Original Job: The backend first fetches the target job's full details from the database, including its original_scheduled_time and its job_group_id.
Calculate Delta: It calculates the time difference: time_delta = new_scheduled_time - original_scheduled_time. (In our example, this would be +2 hours).
Update the Target Job: It performs the first update on the specific job that was targeted: UPDATE scheduled_jobs SET scheduled_time = :new_time WHERE id = :job_id.
Update All Subsequent Jobs in the Group: This is the key step. It then performs a second, bulk update on all other pending jobs that are part of the same sequence and occur after the original time:

UPDATE scheduled_jobs
SET scheduled_time = scheduled_time + :time_delta
WHERE job_group_id = :original_group_id
AND status = 'PENDING'
AND scheduled_time > :original_scheduled_time;
